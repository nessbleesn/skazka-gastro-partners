# Skazka Gastro Partners

Полноэкранная адаптивная web-презентация Парка «Сказка» для ресторанных операторов, локальных гастрономических проектов и потенциальных food-партнёров.

- Production: https://nessbleesn.github.io/skazka-gastro-partners/
- Репозиторий: https://github.com/nessbleesn/skazka-gastro-partners
- Формат: статический HTML, CSS и JavaScript без сборки и backend-зависимостей.

Главный экран использует зацикленные web-копии без аудиодорожки: VP9/WebM 1280×720 для Chromium/Firefox и H.264/MP4 1600×900 для Safari и fallback. При запрете autoplay и в режиме reduced motion остаётся статичный poster.

## Локальный запуск

```powershell
python -m http.server 4173 --directory C:\Users\asmaga\Documents\skazka-gastro-partners
```

Затем открыть `http://127.0.0.1:4173`.

## Управление презентацией

- колесо мыши / скролл — переход по экранам;
- стрелки, Page Up / Page Down, пробел — навигация с клавиатуры;
- `F` или кнопка в правом верхнем углу — полноэкранный режим;
- на мобильных устройствах используется естественная вертикальная прокрутка.

## Где менять данные

Публичные показатели, рабочая сезонность и карточки аттракционов находятся в `content.js`.

Внутренние данные намеренно не выдуманы. Для финализации нужны:

1. фактический и планируемый трафик;
2. прогноз прироста;
3. средний чек и семейная доля;
4. помесячная сезонность;
5. пропускная способность аттракционов;
6. утверждённый генплан с точками питания;
7. название зоны и дата открытия;
8. персональный контакт и конечный получатель формы.

## Форма заявки

Сейчас форма формирует письмо на подтверждённый общий адрес `info@parkskazka.com`. После назначения ответственного адрес меняется в `app.js` и в финальном CTA.

## Публикация

GitHub Pages публикуется автоматически из `main` workflow-файлом `.github/workflows/deploy-pages.yml`. Перед релизом необходимо выполнить локальный desktop/mobile QA, дождаться успешного workflow и повторить проверку публичного cache-busted URL.
